## 1. Penerimaan barang

- Penerimaan akun Firebase disimpan melalui `POST /api/purchase-orders/:poId/receipt`.
- Server memverifikasi token dan peran gudang, membaca PO terbaru dalam transaksi Firestore, lalu mencocokkan seluruh item, SKU, nama, jumlah pesanan, jumlah diterima, dan kondisi.
- Label MATCHED dengan jumlah atau kondisi yang berselisih ditolak. Penerimaan yang berselisih dapat dicatat sebagai DISCREPANCY dan tetap tidak bisa dibayar.
- Firestore Rules menolak penulisan GRN langsung dari klien, termasuk klien dengan peran Super Admin. Server menggunakan Firebase Admin SDK untuk menulis hasil yang sudah diverifikasi.
- Server menambahkan `receiptVerification` yang tidak dapat ditulis klien. Pembayaran membutuhkan penanda ini; label MATCHED pada dokumen lama tidak cukup.
- Dokumen lama berstatus Barang Diterima tanpa penanda verifikasi dapat dibuka lewat Periksa GRN/3-Way Match oleh gudang dan diverifikasi ulang. PO yang sudah selesai tidak dibuka kembali.
- Modal tidak lagi membuat penerimaan 10 unit ketika rincian PO hilang. Jumlah diterima pada GRN baru dimulai dari 0; nama petugas dan surat jalan perlu diisi. Catatan pemeriksaan fisik tidak diisi otomatis.

## Konfigurasi untuk penggunaan di luar emulator

Perbaikan keamanan Firestore belum aktif pada database produksi sampai aturan baru dideploy. Jalur GRN server juga memerlukan identitas Firebase Admin yang memiliki akses Firestore.

1. Jalankan `npm install` untuk memasang dependensi, termasuk `firebase-admin`.
2. Atur konfigurasi server melalui `.env` berdasarkan `.env.example`. Project ID secara default mengikuti `firebase-applet-config.json`; `FIREBASE_PROJECT_ID` hanya diperlukan bila dikonfigurasi secara eksplisit untuk project yang sama.
3. Gunakan Application Default Credentials pada server. Pada hosting Google, pasangkan service account yang memiliki izin Firestore. Untuk pengembangan lokal, `GOOGLE_APPLICATION_CREDENTIALS` dapat menunjuk JSON service account yang disimpan di luar repository. Jangan menaruh kunci tersebut di frontend atau menggunakan awalan `VITE_`.
4. Deploy `firestore.rules` yang sudah diperbarui ke project Firebase yang sama dengan aplikasi. Contoh: `firebase deploy --only firestore:rules --project <project-id-aplikasi>`.
5. Jalankan ulang server setelah konfigurasi dan deploy. Untuk produksi, gunakan `npm run build` lalu `npm start` dengan `NODE_ENV=production`.

Gunakan urutan rilis yang terkoordinasi: sediakan kredensial server dan kode backend/frontend baru, lalu aktifkan aturan baru. Jangan memakai penanda verifikasi manual untuk melewati validasi dokumen lama. Audit ini tidak mengubah kredensial atau menerbitkan aturan ke Firebase produksi.
