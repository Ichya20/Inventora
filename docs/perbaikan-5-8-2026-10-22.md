# Perbaikan temuan 5-8 Inventora

Tanggal: 22 Oktober 2026.

## Perubahan

| Temuan | Perbaikan |
| --- | --- |
| 5. Item PO tidak valid dapat masuk ke database | Pembuatan PO melewati API dengan pemeriksaan peran Warehouse Manager atau Super Admin. Server memeriksa setiap item, jumlah, harga, subtotal, tanggal, serta kesesuaian total. Penyimpanan memakai transaksi dan menolak nomor PO yang sudah ada. Rules lokal menolak pembuatan PO langsung dari klien. Pembacaan rincian penerimaan memakai pemeriksaan array dan menampilkan error untuk PO lama yang tidak lengkap. |
| 6. Penyimpanan gagal tetapi UI menampilkan sukses | Pengeluaran stok dan perubahan faktur menjadi Lunas disimpan sebelum state dan pesan sukses diperbarui. Kegagalan baca, kuota, atau data tersimpan yang rusak membatalkan perubahan. Operasi membaca data tersimpan terbaru untuk mencegah pengurangan stok kosong atau pelunasan berulang dari state lama. |
| 7. Label stok tertinggal dari jumlahnya | Tabel, laporan CSV, dan ringkasan dashboard menggunakan perhitungan status stok yang sama. Stok nol tampil Habis. Batas minimum mengikuti `stockMin`, dengan nilai bawaan 10; hingga dua kali minimum masuk pemantauan. |
| 8. Pengingat mengaku email sudah dikirim | Tombol menghasilkan file draf email `.eml` berisi nomor faktur, pelanggan, tanggal, dan nominal. Pengguna memeriksa penerima lalu mengirim melalui aplikasi email. UI menyatakan bahwa email belum dikirim. |

Inventori dan faktur keuangan tetap merupakan data simulasi lokal pada browser. Perbaikan ini tidak memindahkan keduanya ke Firestore.

## Pengujian ulang

- 32 tes regresi/API lulus, mencakup akses endpoint, validasi PO, kegagalan penyimpanan, pengeluaran stok berulang, status stok, serta isi draf email.
- 8 tes Firestore emulator lulus, mencakup penolakan create dari klien, penyimpanan PO melalui Admin SDK, penolakan ID duplikat, persetujuan, validasi penerimaan, dan syarat pembayaran.
- Pemeriksaan TypeScript `tsc --noEmit` lulus.
- Build frontend Vite dan bundle server esbuild berhasil. Vite memberi peringatan ukuran beberapa chunk di atas 500 kB; tidak ada kegagalan build.
- Pemeriksaan bundle `dist/server.cjs` lulus: endpoint kesehatan mengembalikan HTTP 200; tiga endpoint terlindungi menolak akses anonim dengan HTTP 401; token tidak valid juga ditolak dengan HTTP 401.
- `git diff --check` lulus.

Pesan `PERMISSION_DENIED` selama tes rules berasal dari percobaan akses yang memang harus ditolak. Hasil tes memeriksa penolakan tersebut.

Perintah tes:

```powershell
npm test
npm run lint
# Jalankan emulator terlebih dahulu. Port harus sesuai emulator yang aktif.
$env:FIRESTORE_EMULATOR_HOST='127.0.0.1:8096'
npm run test:rules
```

## Batas verifikasi dan konfigurasi

Konfigurasi serta deployment Firebase diserahkan kepada pemilik project sesuai permintaan terakhir. Tidak ada `.env` atau `.firebaserc` yang dibuat, rules belum dideploy, dan file service account tidak dibaca atau disalin. Tes database hanya memakai project emulator `demo-inventora`.

Server Firebase Admin perlu siap sebelum rules baru diterapkan: pembuatan PO dan penyimpanan penerimaan memakai API server. Pemeriksaan cloud sebelumnya melaporkan Firestore API pada project frontend belum aktif atau belum pernah digunakan; hal ini perlu diselesaikan saat konfigurasi oleh pemilik project.

Pengujian antarmuka melalui browser, login Google nyata, akses database cloud, dan pengiriman email nyata tidak dilakukan. File draf belum diuji dengan aplikasi email pengguna.
